# Задание: система плагинов (M6)

> Вставь перед этим текстом `00-CONTEXT.md`.

## Цель

Расширяемость не хуже pass, но **без сорсинга bash-функций**. Это осознанный
разрыв совместимости (§0): bash-расширения pass, лезущие во внутренности, не
поддерживаются. Взамен даём стабильный контракт.

Строишь `pkg/plugin` и команды `binpass plugin ...` по §4.

## Три уровня

### Уровень 1 — subcommand на PATH (git-style)

Файл `binpass-foo` на PATH или в `$XDG_DATA_HOME/binpass/plugins/` → появляется
команда `binpass foo`. Любой язык.

Замена сорсингу функций — **стабильный CLI обратно в binpass**:

```bash
#!/usr/bin/env bash
: "${BINPASS_STORE:?}" "${BINPASS_BIN:?}"
"$BINPASS_BIN" ls --format=json | jq -r '.[] | select(.used_days_ago > 365) | .path'
```

Экспортируешь: `BINPASS_BIN`, `BINPASS_STORE`, `BINPASS_VERSION`,
`BINPASS_PLUGIN_DIR`, `BINPASS_API=1`, `PASSWORD_STORE_DIR` (для скриптов,
ожидающих pass).

**Машиночитаемый вывод у всех команд** — `--format=json|yaml|template`. Сейчас
он есть только у `ls`; тебе нужно довести до остальных, чтобы плагины не
парсили человекочитаемый stdout. Схема версионируется, ломающие изменения —
только со сменой `BINPASS_API`.

### Уровень 2 — декларативные рецепты

Для типовых вещей код не нужен:

```yaml
name: rotate-github
match: "github.com/*"
steps:
  - generate: { length: 32, symbols: true }
  - open_url: "https://github.com/settings/admin"
  - confirm: "Пароль изменён на сайте?"
  - commit: "Rotate GitHub password"
```

Живут в `~/.config/binpass/recipes/`. Набор шагов держи маленьким и закрытым —
рецепт не должен превращаться в язык программирования.

### Уровень 3 — типизированные плагины через `hashicorp/go-plugin` (gRPC/stdio)

Для глубокой интеграции: свой транспорт синхронизации (`RemotePlugin`), свой
источник identity (`IdentityPlugin`), свой тип секрета (`SecretPlugin`).
Интерфейсы — §4.1. gRPC значит любой язык, и падение плагина не роняет binpass.

**Прочитай §15.2 и реши сам:** уровни 1–2 закрывают 90% кейсов за 10% усилий.
Если уровень 3 раздувает сроки — сделай 1–2 полностью и качественно, а по
третьему представь проект интерфейсов. Так честнее, чем три сырых уровня.

## Модель разрешений — не опциональна

Плагины видят пароли. Без capability-модели это дыра, а не фича.

Манифест `plugin.yaml` обязателен (§4.2): `read_paths`, `write_paths`,
`decrypt`, `network` (белый список хостов), `exec`.

* При установке — показ манифеста и явное подтверждение. `decrypt: true`
  подсвечивается отдельно.
* Гранты в `plugins.lock` **с хешем бинаря**; хеш изменился — переспрашиваем.
* Сеть режется на уровне процесса: наружу только через прокси ядра.
* Уровень 3 запускается с отдельным umask, **без наследования агентского
  сокета**.
* `binpass plugin audit` показывает, у кого какие права.

**Формулируй границы честно.** Полноценной песочницы нет: на уровне 1 плагин —
обычный процесс пользователя и может обойти ограничения. Модель защищает от
небрежного плагина, не от вредоносного. Так и пиши в документации — не
продавай иллюзию безопасности.

Опциональный WASM-рантайм (`wazero`) на уровне 3 даёт настоящую изоляцию, но
без доступа к сети и файлам — годится для трансформаций и валидаторов.

## Дистрибуция

```
binpass plugin search|install|list|info|update|remove|audit
```

Установка по URL работает всегда, с проверкой подписи (minisign). Реестр —
git-репозиторий с индексом, ничего централизованного.

Плагины в `.binpass/plugins/` внутри стора синхронизируются вместе с ним —
удобно, но требует доверия ко всем, у кого есть доступ. **Предупреждай.**

## Критерий готовности (§14)

Внешний плагин ставится и работает **по документации**. Значит: напиши
документацию, дай её человеку, который не читал твой код, и проверь, что он
написал рабочий плагин. Если не может — документация не готова.

## Тесты

* Плагин уровня 1 на bash: устанавливается, вызывается, получает окружение.
* Манифест с `decrypt: true` требует подтверждения; отказ — плагин не ставится.
* Изменение бинаря после гранта → повторный запрос.
* Плагин, объявивший `network: []`, не может ходить в сеть.
* Плагин, объявивший `read_paths: ["a/**"]`, не читает `b/`.
* Падение плагина уровня 3 не роняет binpass.
