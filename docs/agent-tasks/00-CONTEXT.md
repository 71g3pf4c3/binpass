## Проект

`binpass` — переосмысленный `pass(1)`: тот же формат хранилища и та же поверхность
команд, но функциональность, ради которой в pass ставят десяток bash-расширений,
встроена нативно и работает одинаково на трёх ОС.

Полное ТЗ — `ARCHITECTURE.md` в корне репозитория. **Прочитай его целиком перед
началом.** Номера параграфов ниже ссылаются на него.

* Go 1.26, `CGO_ENABLED=0`, модуль `github.com/71g3pf4c3/binpass`.
* Один бинарь `binpass`. Сервера нет.

## Железные правила

1. **Совместимость с pass — это тест, а не обещание.** В `internal/cli/golden/`
   лежит набор, который гоняет настоящий `pass` и binpass на одинаковом сторе и
   сравнивает stdout, коды возврата и дерево. Если твоя фича меняет вывод
   существующей команды — golden-тесты обязаны остаться зелёными.

2. **Ничего своего в сторе.** Состояние синхронизации, кеши, индексы — только в
   `$XDG_DATA_HOME/binpass/` (§1). Внутри `$PASSWORD_STORE_DIR` может лежать
   только то, что понимает pass, плюс `.binpass/plugins/`.

3. **Секреты не попадают в argv, в логи и на диск в открытом виде.** Ввод —
   только с TTY/stdin. Временные файлы — 0600 и в tmpfs, где она есть
   (см. `internal/cli/tmpfile.go`).

4. **Тесты обязательны и должны быть настоящими.** Не «функция вернула nil», а
   «поведение соответствует спецификации». Table-driven. Если можно проверить
   против эталона (настоящий pass, RFC-вектор, реальный сервер в контейнере) —
   проверяй против эталона, а не против собственных ожиданий.

5. **Godoc на каждый экспортированный элемент**, комментарии заканчиваются
   точкой (`godot`), линтер `revive.exported`. Комментарий объясняет **почему**,
   а не пересказывает код.

6. **Не ломай `CGO_ENABLED=0`.** Внешние бинари (`gpg`, `cryptsetup`, `git`,
   `age-plugin-*`) — вызываем через `exec`, не линкуемся.

## Как проверять свою работу

```sh
nix develop                      # go, gpg, pass, age, tree, rofi, fzf, syft
make test                        # весь набор
make cover                       # gate ≥70%
golangci-lint run                # должно быть 0 issues
gofmt -l .                       # должно быть пусто

docker build -f Dockerfile.test -t binpass-test . && docker run --rm binpass-test
docker build -f Dockerfile.e2e  -t binpass-e2e  . && docker run --rm binpass-e2e
```

**Категорически нельзя** запускать тесты против домашнего каталога
разработчика: ни `~/.password-store`, ни `~/.gnupg`, ни системного буфера
обмена. Всё — во временных каталогах и в контейнере. Это не пожелание: один раз
уже был стёрт живой буфер обмена пользователя.

## Стиль коммитов

Conventional commits, тело объясняет **почему**, а не перечисляет файлы.
Пример — `git log -1 a3cf478`.
