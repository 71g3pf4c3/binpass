# Задание: import/export и audit (M2)

> Вставь перед этим текстом `00-CONTEXT.md`.

Два независимых куска, но обоим нужен один и тот же навык: аккуратно обращаться
с чужими форматами. Можно делить между двумя агентами.

---

## Часть A. `pkg/importer` — 60+ форматов

Замена `pass-import`, плюс `binpass export`.

Обязательный минимум: **KeePass (kdbx), Bitwarden, 1Password, LastPass, Chrome,
Firefox, Enpass, pass, gopass**. Дальше — по убыванию популярности.

### Как строить

Один интерфейс, много реализаций:

```go
// Importer читает чужой формат и отдаёт записи потоком.
type Importer interface {
    Name() string
    Detect(io.Reader) bool          // автоопределение по содержимому
    Import(io.Reader) iter.Seq2[*Entry, error]
}
```

Автоопределение формата по содержимому важнее, чем по расширению: пользователь
не обязан знать, что у него за CSV.

### Что реально ломается

Чужие форматы — **самое хрупкое место в проекте**. ТЗ (§12) прямо требует
fuzz-тесты на парсеры импорта. Не пропускай это.

* CSV с переводами строк внутри полей, с BOM, в CP1251.
* Один и тот же экспорт из разных версий приложения — разные колонки.
* Дубликаты имён после нормализации путей.
* Записи, чьё имя после преобразования вылезает за пределы стора (`../`) —
  `pkg/storage` это отобьёт, но проверь, что отбивает и есть тест.
* Пустые пароли, пароли-эмодзи, поля длиной в мегабайт.
* KDBX с аттачментами → бинарные записи (`name.b64.gpg`, §1).
* TOTP-секреты в разных представлениях → приводи к `otpauth://` (`pkg/otp`).

**Обязательно** `--dry-run`: показать план, ничего не записав. Импорт пароля —
операция, которую пользователь делает один раз и в панике; дай посмотреть.

Пароли от исходных файлов (kdbx) — только с TTY/stdin, **никогда из argv**.

### Тесты

Табличные, на реальных экспортах (сгенерируй сам, не бери чужие реальные
пароли). Fuzz на каждый парсер. Golden: импорт → экспорт → импорт даёт то же
самое.

## Часть B. `pkg/audit` — `binpass audit`

Замена `pass-audit`, но полезнее.

### Что проверять

1. **Утёкшие пароли — HIBP по k-anonymity.** Считаешь SHA-1, отправляешь
   **первые 5 символов**, получаешь список суффиксов, сравниваешь локально.
   Полный хеш наружу не уходит никогда. Это не деталь реализации, это суть:
   audit не должен сливать пароли в облако.
   Кеш ответов, offline-режим, уважение rate limit.

2. **Слабые** — `zxcvbn-go`, не длина и не «есть ли спецсимвол».

3. **Переиспользованные** — одинаковые пароли в разных записях. Сравнивай
   хеши в памяти, зануляй буферы.

4. **Просроченные** — вместе с `binpass expire` (TTL на записи).

### Вывод

`--format=json` обязателен (нужен плагинам). Человекочитаемый — с группировкой
по severity.

**Никогда не печатай сам пароль** — ни в отчёте, ни в JSON. Только имя записи и
вердикт.

### Осторожно с производительностью

audit расшифровывает **весь стор**. Если recipient аппаратный — это касание
токена на каждую запись (§3.3). Предупреди пользователя и дай `--parallel`,
но не делай его дефолтом при аппаратном ключе.

### Тесты

* k-anonymity: подними заглушку HIBP в контейнере, проверь, что уходит ровно
  5 символов префикса и ничего больше.
* Известный слабый пароль → detected. Известный сильный → clean.
* Переиспользование находится, пароли в выводе не светятся.
