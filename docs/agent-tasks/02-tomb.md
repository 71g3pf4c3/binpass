# Задание: tomb и coffin (M5)

> Вставь перед этим текстом `00-CONTEXT.md`.

## Цель

Стор не просто зашифрован по файлам, а **целиком скрыт**, когда не используется:
не видны ни имена записей, ни структура, ни факт существования. Это радикальное
решение проблемы «провайдер видит имена записей» (§8.4, §10).

Строишь `pkg/tomb` и команды `binpass tomb init|open|close|status` по §7.

## Три бэкенда

### Coffin — кроссплатформенный, дефолт

Весь стор — один зашифрованный архив `store.coffin.age`. Открытие: расшифровка
в приватный tmpfs-каталог (Linux) или каталог 0700 с явным затиранием
(macOS/Windows). Закрытие: перешифровка + `shred`.

Работает везде, включая Windows, без прав root. Ключ — обычный age-recipient,
значит **аппаратные ключи поддерживаются сразу**.

Слабое место, которое надо честно митигировать: plaintext-каталог во время
сессии. tmpfs, `mlock` для мелких файлов, автозакрытие по таймауту и на события
ОС.

### Tomb — Linux, максимальная защита

LUKS-контейнер через внешний `cryptsetup` (**не** линковка с libcryptsetup —
§7.3, иначе теряется статика и кроссплатформенная сборка).

* Plaintext существует только в маппинге dm-crypt, на диск не попадает.
* Ключ-файл контейнера сам зашифрован age/GPG → аппаратный токен как ключ.
* Нужен root или polkit-политика — **предупреждай честно**, не пытайся обойти.
* **Совместимость:** существующий tomb от `pass-tomb` должен открываться.
  Проверь на реальном контейнере, созданном pass-tomb.

### Sparsebundle — macOS

Encrypted APFS sparse bundle через `hdiutil`, ключ в Keychain или на токене.
По защите ближе к tomb, по удобству к coffin.

## Автозакрытие — половина ценности фичи

Вешается на: таймер, блокировку экрана, suspend, logout, `binpass-agent forget`.

Это три разных механизма на трёх ОС:
* Linux: D-Bus (`org.freedesktop.login1`, screensaver-сигналы) через
  `godbus/dbus/v5` — чистый Go, без CGO.
* macOS: IOKit-нотификации.
* Windows: WinAPI.

Критерий готовности M5 (§14): **автозакрытие по screenlock работает на трёх ОС.**

При аварийном завершении `binpass doctor` должен находить незакрытый контейнер.

## Тесты

* LUKS — в привилегированном контейнере (`--privileged`, `/dev/loop`).
* Coffin — везде, включая Windows-раннер.
* Открытие контейнера, созданного настоящим `pass-tomb`.
* Аварийное завершение при открытом контейнере → следующий запуск это видит.
* Проверь, что после `close` plaintext действительно не остался: ни в каталоге,
  ни в списке файлов tmpfs.

## Честность в документации

§10 требует прямо сказать: `shred` на SSD с wear-leveling **не даёт гарантий**.
Напиши это в помощи к команде, а не только в README. Пользователь, выбирающий
tomb, должен понимать границы защиты.
